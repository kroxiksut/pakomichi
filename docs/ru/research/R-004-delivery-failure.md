# R-004 — Socket activation, атомарные снимки и сбои

[English](../../en/research/R-004-delivery-failure.md) · **Русский**

Результат этого протокола обязателен до утверждения CAS, HTTP snapshots и offline/freshness поведения.

## Гипотеза

Одна loopback HTTP-служба, активируемая systemd socket, может надёжно отдавать отдельные подписанные логические APT/RPM-репозитории при параллельном обращении нативных менеджеров. Immutable generations и CAS не допускают смешивания метаданных разных версий.

## Исследования

1. В контейнере/VM с systemd (для socket tests необходима настоящая init среда) подготовить handler `Accept=no`, проверить холодный/параллельный GET, рестарт, таймаут и запуск после падения процесса.
2. Создать два поколения индексов, имитировать переключение во время `apt update` и скачивания пакета; сравнить digest полученного индекса/пакета. Повторить для DNF4/DNF5.
3. Проверить APT `Acquire-By-Hash` и `Valid-Until`, подписанный `InRelease`; обеспечить, что `304` на GitHub считается подтверждением только при корректной условной проверке.
4. Имитация сетевого разрыва посередине загрузки, download timeout, неверный SHA, исчерпание диска, завершение процесса во время staging/rename/fsync, повреждённая SQLite, потеря signing key.
5. Зафиксировать RAM idle, время запуска, производительность запросов и объем кеша — реальные измерения, без произвольных обещаний.
6. Проверить, что **чужие** APT/DNF репозитории не затронуты, а установленное приложение не исчезает после остановки/удаления мостовой службы.
7. Проверить защиту HTTP от некорректного пути, symlink, SSRF/private IP redirect и запрета POST/административных команд.

## Приёмка

PASS: каждый опубликованный снимок полностью самосогласован; ранее опубликованные bytes остаются корректны; при ошибке источника нет подмены или выдачи частичного файла; восстановление описано воспроизводимо.

**Fallback:** обычная systemd service с тем же протоколом HTTP и файлохранилищем, если socket activation не удовлетворяет требованиям конкретной ОС. Для офлайна без доступного пакета честная ошибка, не искусственная подстановка.
