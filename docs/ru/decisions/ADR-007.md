# ADR-007 — Одна HTTP-служба, много логических репозиториев

[English](../../en/decisions/ADR-007.md) · **Русский**

**Статус:** принято как проектное решение (концепция); эксплуатационные свойства проверяются исследованиями.
**Дата:** 2026-10-18.

## Контекст

Можно получать пакеты по запросу, но не держать постоянно работающий процесс. `file://` без предзагрузки не может обеспечить lazy downloading.

## Решение

По умолчанию loopback HTTP со systemd socket activation, один процесс/кеш и отдельные подписанные metadata endpoints для каждого источника. Управляющий API — отдельный локальный IPC.

## Альтернативы и причины отказа

Единый логический репозиторий для всех Git-источников / постоянная служба как единственный способ / file-only как основной путь — не выбраны.

## Последствия и ограничения

Решение обязательно для проектирования API, состояния и тестов. Если конкретная версия ОС не обеспечивает указанное поведение, нельзя объявлять поддержку этой комбинации без ограничения функциональности. Любое изменение решения требует новой superseding ADR и подтверждения владельца проекта.

## Подтверждение

R-004 проверяет работу с параллельными запросами и отказами; fallback — ordinary systemd service.
