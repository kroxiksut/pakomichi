# ADR-026 — Матрица поддержки 0.1 по итогам исследований

[English](../../en/decisions/ADR-026.md) · **Русский**

**Статус:** принято владельцем проекта 2026-10-20. ADR-014 остаётся в силе; это решение сужает платформы, которые 0.1 может заявить, и ничего не заменяет. `testing/release-gate.md` и `testing/matrix.md` следуют ему.  
**Дата:** 2026-10-20.

## Контекст

ADR-014 задаёт рамки 0.1 как DEB/APT и RPM/DNF4/DNF5 в проверенных окружениях, а `testing/matrix.md` требует, чтобы альфа перечисляла только проверенные сочетания. R-001, R-002, R-004, R-005 и R-006 завершены; R-003 завершён только в части, доступной только для чтения. Исследования шли на разных наборах платформ, поэтому ни одна платформа пока не покрыта всеми исследованиями и ни одна — самим Pakomichi.

## Решение

1. **Правило допуска к заявлению в 0.1.** Сборку дистрибутива можно указать как поддерживаемую в 0.1 только после того, как на этой самой сборке выполнены: матрица выбора R-001; для RPM — матрица R-002; подмножество доставки R-004 (активация через сокет, поколения со штатными клиентами, сторонние репозитории и удаление) на ВМ с настоящим systemd и режимом SELinux или AppArmor по умолчанию для дистрибутива; записана версия SQLite и пройдены тесты миграций (ADR-020); E2E-01 или E2E-02 и применимые N-тесты с собственным пакетом Pakomichi. Для AlmaLinux и Fedora подмножество доставки и прогон E2E выполняются на ВМ с SELinux в принудительном режиме (enforcing) до заявления поддержки.
2. **Первые цели.** Первые цели 0.1 — Debian 12, AlmaLinux 9, Fedora 44 и Astra Linux 1.8.6 на уровне `base(orel)` (обычная команда обновления `apt-get dist-upgrade`, ADR-022). У Debian 12, AlmaLinux 9 и Fedora 44 уже есть исследовательские доказательства R-001, R-004 и (для RPM) R-002. У Astra Linux 1.8.6 на уровне `base(orel)` есть доказательства R-001, но из R-004 — только отключение питания, поэтому до заявления нужен прогон доставки (подмножество R-004 из пункта 1) на этой самой сборке. Каждой первой цели по-прежнему нужно всё из пункта 1, что таблица отмечает как отсутствующее.
3. **Условные и более поздние цели.** Debian 13, Ubuntu 24.04, Ubuntu 26.04 и AlmaLinux 10 можно добавить в 0.1, только если для них выполнен пункт 1. РЕД ОС — более поздняя цель: она не входит в первые цели, а РЕД ОС 8 или 7.3 заявляется, только когда для этой сборки выполнен пункт 1. Иначе эти платформы перечисляются как «не проверено», а не как поддерживаемые.
4. **Не заявляется в 0.1.** Astra Linux с замкнутой программной средой (ADR-025); Astra Linux 1.7 на любом уровне (владелец считает её устаревшей, 21.10.2026; доказательства R-001 и SQLite для неё сохраняются); РЕД ОС 7.3, пока не проверена её версия SQLite (ADR-020; Astra Linux 1.7.6 проверена 20.10.2026); ALT Linux; arm64 и aarch64.
5. **Заявления о возможностях.** Strict и Attested заявляются только после завершения R-003 и выбора промышленного верификатора (ADR-005, пункт 9 ADR-017). Исключение Attested для RPM ждёт R-003 (ADR-023). Примечания к выпуску указывают вывод R-005: доказательства Strict или Attested публикует лишь меньшинство репозиториев выборки. ADR-027 допускает уровень Pinned в 0.1 только за явным согласием для каждого источника и ручным подтверждением каждого релиза; уровень Signed отложен до 0.2.
6. **Условия выпуска.** `testing/release-gate.md` и `testing/matrix.md` обновлены в обоих языках по пунктам 1–5.

## Альтернативы и причины отказа

- **Заявить каждую платформу, на которой шёл R-001:** R-001 проверяет только решения менеджера пакетов, а не доставку, подписи или Pakomichi.
- **Заявить только AlmaLinux 9:** единственная платформа со всеми исследованиями, но тогда в 0.1 не остаётся ни одной APT-платформы.
- **Выводить поведение сборок DNF из upstream DNF:** R-001 показал, что сборки РЕД ОС отличаются.

## Последствия

Исследовательская работа для первых целей — прогон на ВМ с принудительным SELinux или AppArmor и собственными пакетами Pakomichi, а также прогон доставки на Astra Linux 1.8.6 на уровне `base(orel)`; каждая дополнительная платформа добавляет недостающие исследования своей строки. Число поддерживаемых платформ в 0.1 может оказаться меньше списка R-001, что `release-gate.md` прямо разрешает.
