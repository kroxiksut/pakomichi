# ADR-019 — serde и serde_json как слой сериализации

[English](../../en/decisions/ADR-019.md) · **Русский**

**Статус:** принято владельцем проекта.  
**Дата:** 2026-10-20.

## Контекст

В P0-003 версионированный контракт причин (JSON-конверт v1) реализован на `serde =1.0.229` (feature `derive`) и `serde_json =1.0.154`. Журнал решений откладывал утверждение этих crate до P0-004, а ADR-017 их не называет. Предстоящей работе нужен слой сериализации для версионированного JSON:
- IPC между непривилегированным ядром и applier;
- статусное API только для чтения;
- записи доказательств и решений;
- разбор ответов GitHub API (P2-001).

`rust-engineering.md` требует, чтобы у форматов IPC, хранения и сериализованных решений была явная версия и один нормативный тип, а `Debug`/`Display` никогда не служили стабильным форматом.

Зафиксированный граф этих двух crate: `serde`, `serde_core`, `serde_derive` (с `proc-macro2`, `quote`, `syn`, `unicode-ident` во время сборки), `serde_json`, `itoa`, `memchr` и `zmij`. Все они под MIT и/или Apache-2.0 (у `unicode-ident` также Unicode-3.0), взяты с crates.io и проходят текущую политику `cargo deny`.

## Решение

1. Утвердить `serde` (features `derive` и стандартная `std`) и `serde_json` (только стандартные features) с точным закреплением версий в `[workspace.dependencies]`. Обновления проходят обычное ревью зависимостей и `cargo deny`.
2. **Форматы, которыми владеет Pakomichi** (события причин, сообщения IPC, статусное API, записи доказательств и решений). Каждое сообщение верхнего уровня несёт явный `schema_version`. Его тип для передачи использует `#[serde(deny_unknown_fields)]` и превращается в проверенные доменные типы через `TryFrom`, как уже сделано в P0-003. Сообщение с неизвестным полем или неподдерживаемой версией отвергается со стабильным кодом причины и никогда не принимается частично.
3. **Чужие форматы** (ответы GitHub REST и подобные): `deny_unknown_fields` не использовать, потому что поставщик добавляет поля. Десериализовать в отдельные типы только используемые поля и проверять их. Отсутствие или неверный тип обязательного поля считать ошибкой. Никогда не выводить доверие из поля, которое не проверено явно.
4. **Ограничения:**
   - размер входа ограничивается до разбора;
   - стандартный предел рекурсии `serde_json` сохраняется (`unbounded_depth` не включать);
   - `arbitrary_precision`, `preserve_order` и `raw_value` не включать без отдельного решения;
   - числа-идентификаторы и размеры разбираются в явные целочисленные типы, никогда через `f64`.
5. **Вне области:**
   - строки SQLite (их обрабатывает `rusqlite` напрямую);
   - метаданные DEB/RPM (границы процессов ADR-017);
   - файлы репозиториев APT/RPM (их пишут отдельные генераторы);
   - формат файла конфигурации: ему нужно отдельное решение, когда такой файл появится.

## Альтернативы и причины отказа

- Ручное кодирование и декодирование JSON: больше кода на важных для безопасности путях разбора и никакого выигрыша в проверяемости при таком объёме форматов.
- `miniserde` или `nanoserde`: меньше, но слабее поддерживают строгую обработку полей и проверяемое преобразование, и их меньше проверяли и используют в экосистеме.
- SIMD-парсеры JSON: производительность не ограничение для таких размеров сообщений, а они добавляют `unsafe`-код и зависимости.

## Последствия

`Cargo.toml` уже соответствует пунктам 1 и 4 (лишних features нет). `src/error.rs` следует пункту 2 и до разбора ограничивает событие причины размером `MAX_REASON_EVENT_JSON_BYTES`. Клиент GitHub API (P2-001) должен следовать пункту 3. Для этого нужен тест: неизвестные поля поставщика допускаются, а отсутствие обязательного поля приводит к ошибке. `rust-engineering.md` ссылается на этот ADR.

## Проверка

`scripts/quality.ps1`:
- тесты контракта причин отвергают неизвестное поле и неподдерживаемый `schema_version` (`unknown_schema_versions_and_fields_are_rejected`);
- они же отвергают вход больше предела до разбора (`oversized_input_is_rejected_before_parsing`);
- `cargo deny` проверяет граф зависимостей.

Каждый новый тип собственных сообщений должен добавить такие же два теста.
