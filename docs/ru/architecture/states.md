# Модель состояний и переходов

[English](../../en/architecture/states.md) · **Русский**

## Источник

`discovered` → `registered` → `observing` → `active` → `suspended` / `disabled`; из `suspended` в `active` только после устранения причины и повторной проверки. `disabled` не удаляет `ForgeRepository` до выполнения явной операции удаления.

| Событие | До | После | Правило |
|---|---|---|---|
| `source add` | отсутствует | discovered/registered | Закрепить ID репозитория и владельца |
| обнаружение конфликтующего системного пакета | registered | observing | Не менять поставщика |
| явное согласие + успешная симуляция | observing | active | Применить только наши файлы политики |
| чужой repo ID по старому URL | любое активное | suspended | Никакого автоматического relink |
| смена владельца при том же ID | active | suspended | Требуется явное подтверждение |
| недействительная аттестация | active | suspended или исключение конкретного выпуска | По масштабу нарушения, не стирать подтверждённую историю |
| выбранный пакет больше не доступен | active | observing/suspended package | Не переключаться на форк |
| временно нет сети | active | active + stale status | Использовать последний доверенный снимок лишь по freshness policy |
| достигнута максимальная свежесть (DNF) | active | active + `E_SOURCE_STALE` | Опубликовать подписанное пустое поколение; установленные пакеты остаются; успешный `sync` возвращает предложение (ADR-024) |
| явное согласие на Pinned | registered/observing | observing | Дальше допустим только `supplemental`; каждый релиз по-прежнему требует подтверждения (ADR-027) |
| включена замкнутая программная среда (Astra Linux) | любое | observing (активация запрещена) | Удерживать каждый артефакт с кодом `E_EXECUTION_POLICY` (ADR-025) |
| пользователь удалил источник | любое | disabled/deleted | Приложения остаются установленными; файлы репозиториев источника удаляются |

## Версия / артефакт

`discovered → candidate → verified → eligible → published → retired`. Ответвления `held` (конфликт/совместимость, доказательство ниже нижней границы доверия `E_EVIDENCE_DOWNGRADE`, релиз Pinned в ожидании подтверждения `E_RELEASE_APPROVAL_REQUIRED`), `rejected` (доверие/подмена), `revoked` (явная блокировка). `verified` ≠ `eligible`: исходный файл подлинный, но может быть несовместим. Для источника Pinned `verified` означает, что администратор подтвердил точный digest, а не что прошла криптографическая проверка.

Нижняя граница доверия источника (`pinned` < `attested` < `strict`) только повышается; её понижение отклоняется (ADR-027).

## Снимки

`building → signed → verified → staged → published → retired → collected`. `failed` из любого состояния до published; опубликованный снимок **не модифицируется**. ID поколений монотонны и никогда не используются повторно, а `current` никогда не возвращается к более старому поколению. Выведенное из обращения поколение остаётся достижимым как минимум в течение максимальной свежести (DNF) или своего `Valid-Until` (APT) плюс запас; сборка — по достижимости плюс это окно, никогда только по числу поколений (ADR-024). RPM-поколения переключаются не чаще одного раза за интервал обычной проверки, кроме `sync --force` и пустого поколения после максимальной свежести.

## Установленное состояние

Pakomichi **наблюдает** за APT/dpkg или DNF/rpm; он не единственный реестр установленных пакетов. Расхождения выставляют `external_change_detected`, не приводят к самостоятельной переустановке.

## Ошибки

Обязательны machine-readable codes, указанные в `docs/ru/specifications/errors.md`, и понятная человеку причина: что произошло, какой файл/пакет затронут, можно ли продолжить, требуется ли выбор администратора.
