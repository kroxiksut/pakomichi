# Модель данных — семантическая спецификация

[English](../../en/architecture/data-model.md) · **Русский**

Таблицы ниже описывают смысл; физические столбцы, индексы и миграции проектируются отдельно. Все идентификаторы входных Git-данных — недоверенный ввод до проверки.

| Сущность | Обязательные поля и инварианты |
|---|---|
| `ForgeRepository` | внутренний UUID, forge, **постоянный repo ID**, owner ID, canonical URL, first_seen, last_verified, состояние, предыдущие адреса, нижняя граница доверия (`pinned`/`attested`/`strict`, никогда не понижается), время согласия на Pinned; `(forge,repo_id)` уникально |
| `PackageFamily` | UUID, repository UUID, имя/назначение, разрешённые имена в конкретной экосистеме, текущая ревизия набора, согласие пользователя |
| `PackageIdentity` | family UUID, ecosystem (`deb`/`rpm`), native name, allowed arches; строго не путать Git tag и native version |
| `ReleaseRecord` | release ID, tag, commit (верифицированное значение), дата, канал по отдельной политике, immutable claim, проверенное состояние |
| `Artifact` | asset ID, native package tuple, exact filename, SHA-256, size, release ID, source ID, build variant (`unknown` допустимо), verification evidence ID **или** ID подтверждения релиза (никогда оба), режим доверия к RPM-пакету (Native или исключение Attested, ADR-023) |
| `TrustEvidence` | тип Strict/Attested, доверенная root chain, подписант, source repo ID, проверяемый SHA, predicate, время проверки, версия проверяющего, digest сохранённых bundle (ADR-034); только append-only audit |
| `ReleaseApproval` | источник, релиз, подтверждённый SHA-256, время, запись; подтверждение администратором одного релиза источника Pinned (ADR-027); требует согласия на Pinned для источника; append-only |
| `SourcePolicy` | repo ID, family/package, режим observing/active/suspended, allowed channel, accepted trust modes, выбранный нативный источник, штатные ограничения |
| `InstalledObservation` | native package, версия, arch, reported repository if proven, confidence, время, фактические данные менеджера; **не первичный источник истины** |
| `OSInventory` | distro ID/version, manager/version, arch, enabled repos, installed packages, apt/dnf priority, timestamp; пересчитываем при изменениях |
| `ArtifactCache` | content SHA, bytes path, verified state, refcount/pins, download state; никогда не использовать filename как идентичность |
| `Snapshot` | generation (монотонный, никогда не используется повторно), repo, native backend, list manifests, hashes, signatures, valid_from/until, state staged/published/retired, reserved CAS refs, срок удержания |
| `DecisionLog` | event ID, object ID, rule/version, allow/hold/deny, human-readable reason, evidence, timestamp; воспроизводимость решений. Только дописывание; доказательство — канонический JSON фактов `policy::Facts`; у `allow` пустой код причины; решение, равное последнему решению объекта по тем же фактам, повторно не пишется; воспроизведение записи заново решает её факты и сообщает о другом исходе, изменившейся версии правила или нечитаемых фактах (P2-009b) |
| `NameActivation` | источник, экосистема, родное имя, время активации, время окончания; журнал активаций (миграция 0003). Имя открыто не более чем в одном источнике; строка только закрывается, один раз, и не удаляется; «активировано раньше» в решении о допуске — открытая строка источника (P2-009b) |
| `FamilyOutsider` | семейство, экосистема, родное имя (миграция 0005, ADR-036, пункт 3): имя источника со строкой идентичности, которое не входит в семейство, потому что замечено вне семейства или исключено из него, пока на него ссылаются артефакты. Снимает пометку только подтверждённое семейство |
| `EvidenceBundle` | доказательство, источник, SHA-256 bundle (миграция 0007, ADR-034, пункт 1): bundle, по которым проверено доказательство `TrustEvidence`, не больше 16, хранятся байт в байт в хранилище blob, которое никогда не собирает bundle, на который есть ссылка. Только добавление; привязка к доказательству того же источника. Доказательства, записанные до миграции, bundle не называют |
| `EvidenceFullCheck` | источник, время проверки (миграция 0006, ADR-037, пункт 1): последняя полная проверка доказательств на площадке. Между полными проверками записанное доказательство тех же байтов того же asset переиспользуется; одна строка на источник, её заменяет каждая полная проверка |
| `AttestedSigner` | источник, путь workflow, правило ref (`tag` или `refs/heads/<ветка>`), время подтверждения (миграция 0004, ADR-036, пункт 1). Только дописывание; последняя строка источника — его подписант, а источник без строки допускается только на уровнях Strict и Pinned |
| `AdminOperation` | ID, desired state, previous hashes, staged files, apply/rollback status; восстановление после прерывания между SQLite и конфигурацией. Для APT: `planned` → `verified`, `rolled_back` или `failed`, после восстановления — `reconciled` (`delivery-recovery.md`) |

## Ключевые связи

`ForgeRepository 1 → N PackageFamily 1 → N PackageIdentity`; `ForgeRepository 1 → N ReleaseRecord 1 → N Artifact`; каждый `Artifact` связан с разрешённым `PackageIdentity` и `TrustEvidence`; Snapshot ссылается на ровно определённые артефакты по хешам.

Семейство — **не** wildcard по префиксу имени. Два разных пакета одного релиза могут относиться к разным семействам. Нативные `Provides`, `Obsoletes`, `Replaces` не означают разрешение распространять произвольный новый системный пакет.

## Согласованность и уникальность

- Один `source` никогда не переназначается на другой `repo ID`. Передача владельца требует отдельного утверждения.
- Ключ закреплённой записи: `(forge, repository_id, release_id, asset_id, verified_digest)`; существующая запись не перезаписывается при смене digest.
- Артефакт ссылается только на доказательство, предмет которого — его собственный digest. До проверки доказательства нет, и артефакт не может быть `verified`, `eligible`, `published` или `retired`; присоединённое доказательство не заменяется и не удаляется.
- Bundle, названные в доказательстве, остаются в хранилище блобов, пока существует доказательство; доказательство принадлежит одному источнику, и артефакту другого источника с тем же digest нужно своё (ADR-034).
- Для источника Pinned место доказательства занимает подтверждение релиза: оно покрывает ровно подтверждённые digest этого релиза и требует согласия источника на Pinned. Уровень Pinned не является типом `TrustEvidence`, потому что у него нет криптографического доказательства.
- Не объявлять `source_of_installed_package=Git` из совпадения имени/версии. Если история установки не доказана — `unknown`.
- Новый Snapshot нельзя сделать `published`, пока все его индексы, подписи и резервирования файлов согласованы.
- Пользовательский выбор применён успешно лишь после сверки с фактическими настройками APT/DNF.
- При необратимой ошибке БД не реконструировать доверие по произвольной повторной выборке API; требуется доверенная резервная конфигурация или повторное подтверждение.

## Индексы БД / масштабирование

Индексировать repo ID, family/name/backend, native version (сравнение по нативному компаратору, **не лексикографически**), release ID, SHA256, state. Журнал/история отделены от кешируемых API ответов.
