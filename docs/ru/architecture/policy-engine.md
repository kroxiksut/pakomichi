# Политика допуска и выбора источника

[English](../../en/architecture/policy-engine.md) · **Русский**

## Приоритет решений

1. **Идентичность:** source repo ID/owner ID совпадают с закреплёнными; при переносе owner — suspend.
2. **Происхождение:** проверяемая аттестация/immutable policy и точные байты; противоречие → reject. Релиз с более слабым доказательством, чем нижняя граница доверия источника, → hold с `E_EVIDENCE_DOWNGRADE`; релиз Pinned без подтверждения администратором его точных digest → hold с `E_RELEASE_APPROVAL_REQUIRED` (ADR-027).
3. **Состав:** имя+артефакт входят в разрешённое семейство; попытка захвата системного пакета → hold. Артефакт удерживается с `E_SYSTEM_PACKAGE_CONFLICT`, если любой его `Provides` или любой `Obsoletes`/`Replaces` при любом ограничении версии называет элемент системного пространства имён (пункт 2 ADR-022). Штатные менеджеры такой проверки не делают, поэтому её выполняет допуск.
4. **Подходящий выпуск:** выбранный канал, нативная версия, архитектура, зависимости, совместимость.
5. **Конфликты:** анализ установленного состояния и доступных ОС-источников (не только сравнение номеров версий).
6. **Реализуемость в штатном менеджере:** если невозможно выразить выбранную политику — observing/hold, без ложного `preferred`.
7. **Публикация:** только allow → подписанный снимок.

## Базовые режимы источника

- `observing`: только информация, ничего не публикуем.
- `supplemental`: предпочтительны системные источники; Git-пакет используется, когда политика и нативное разрешение допускают. Имя, установленное из другого включённого источника или доступное в нём, либо поставляемое дистрибутивом как приложение, в этом режиме не активируется (`E_NAME_PROVIDED_ELSEWHERE`).
- `preferred`: явное согласие пользователя и подтверждённая нативная политика только для разрешённых имён; без смены другого поставщика по умолчанию. Перенос имени из другого источника — явная миграция (ADR-012, E2E-04). Источник Pinned этот режим никогда не использует (ADR-027).
- `suspended`: конфликт/ошибка; не публиковать новый ненадёжный материал.

## Главный конфликт

APT выбирает версию по priorities, **но не гарантирует выбор конкретного экземпляра одинаковой версии** из двух источников. Поэтому одинаковая версия с различными байтами — `E_SOURCE_AMBIGUOUS` на любой платформе; ни pin APT 2.8+, ни priority DNF заменой не считаются (R-001, пункт 1 ADR-022).

## Без неявной смены издателя (ADR-022)

R-001 показал, что обычное обновление на каждом проверенном менеджере меняет издателя, когда другой включённый источник предлагает более высокую версию того же имени. Для каждого активированного имени, включая каждого члена активированного семейства:

- **APT:** `Pin-Priority: 990` для активированных имён с сопоставлением через `Pin: release o=…,l=…` логического репозитория источника; никогда `Pin: origin` (все репозитории обслуживает один loopback-хост) и никогда 1000 или выше (это допускает понижение версии).
- **DNF:** priority репозитория лучше, чем у репозиториев дистрибутива, а `includepkgs` ограничен активированными именами. `allow_vendor_change` читается и выводится в отчёт, но никогда не записывается и на него не полагаются; `excludepkgs` в чужие репозитории никогда не записывается.
- **Последующие обновления из другого источника**, включая обновления безопасности дистрибутива, издателя не меняют. `pchi status`, `pchi doctor` и status API показывают заметное уведомление с названием другого источника и версией; смена остаётся явным решением пользователя.

Защита показывается под обычной командой обновления каждого дистрибутива: `apt upgrade`/`apt full-upgrade` в Debian и Ubuntu, `apt-get dist-upgrade` в Astra Linux, `dnf upgrade` на платформах DNF. Каждое правило проверяется на каждой поддерживаемой сборке дистрибутива, а не выводится из версии менеджера: RED OS отличается от upstream DNF в `reinstall`, значениях по умолчанию и опциях.

## Замкнутая программная среда Astra Linux (ADR-025)

Пока замкнутая программная среда включена (или это нельзя исключить), Pakomichi отказывается активировать источники и удерживает каждый артефакт с кодом `E_EXECUTION_POLICY`, а не предлагает его как обновление; удержание не зависит от содержимого артефакта.

## Нельзя

- Делать вид, что локальная БД предпочтения воздействует на самостоятельный `apt upgrade`.
- Менять чужие репозитории/порядок их файлов ради тихой победы приоритета.
- Добавлять `glibc`, `openssl`, `python3` из Git и скрывать эту операцию внутри разрешённого семейства.
- Автоматически откатывать на меньшую версию или переключать stable → prerelease.
- Требовать `APT::Get::EnableUpgrade` или любое другое изменение политики APT или DNF дистрибутива.
- Судить о состоянии источника по коду выхода `apt-get update` (он равен 0, когда источник недоступен); вместо этого использовать собственное состояние Pakomichi (пункт 6 ADR-022).

## Ядро решения (P2-009a)

`src/policy` решает один артефакт по версионированным фактам: об источнике (запрошенный режим, идентичность, согласие на Pinned, показано ли, что родной менеджер выбирает источник, выключена ли политика исполнения) и об артефакте (доказательства, изменённый закреплённый asset, инспекция, канал, системное пространство имён, допуск семейства, проверка совместимости, другой источник с той же версией, имя, предоставленное в другом месте, более ранняя активация, подтверждённая миграция). Правила идут в порядке приоритета решений выше, и решает первое возражение; каждое решение называет своё правило и его версию.

- Что делает код, задаёт столбец поведения в `specifications/errors.md`, это проверяет тест: коды с «Reject» (`E_ASSET_MUTATED`, `E_ATTESTATION_INVALID`, `E_ARTIFACT_MALFORMED`) отвергают байты, коды с «Suspend» (`E_REPO_ID_CHANGED`, `E_OWNER_TRANSFER`) приостанавливают источник и удерживают его артефакты, остальные коды удерживают.
- Действующий режим: изменившаяся идентичность приостанавливает источник; включённая или неизвестная политика исполнения переводит его в наблюдение и удерживает каждый артефакт (ADR-025); `preferred` без доказательства родного выбора или для источника Pinned становится `observing`, никогда — ложным `preferred`. Допустимые артефакты наблюдаемого источника разрешены, но не публикуются.
- Релизу Pinned нужны и согласие источника на Pinned, и одобрение релиза; одобрение без согласия — понижение.
- Собственное имя: часть ОС — конфликт с системным пакетом; имя, которое дистрибутив поставляет как приложение или предоставляет другой источник, — `E_NAME_PROVIDED_ELSEWHERE`; оба случая прощаются, если этот источник активировал имя первым (ADR-022, пункт 3), `Provides` системного пакета — никогда. Имя забирает только явная миграция источника не Pinned в режиме `preferred` (ADR-012, ADR-027, пункт 5).
- Факты сериализуются в канонический JSON со `schema_version` 1, неизвестные и отсутствующие поля отвергаются; одинаковые факты дают одно решение и один digest, поэтому решение, записанное в журнал `decision_log` (только дописывание), можно воспроизвести (P2-009b).

## Решение vs транзакция

`eligible` — опубликована корректная кандидатная версия по текущему снимку инвентаризации. Оно **не равно** гарантия, что любой будущий `apt upgrade` безопасен. Доказательство выбора/плана оформляется в тестах адаптера, ограничения остаются видимыми.
