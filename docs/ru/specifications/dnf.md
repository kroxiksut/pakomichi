# Контракт RPM/DNF4/DNF5

[English](../../en/specifications/dnf.md) · **Русский**

- Каждый Git-источник имеет уникальный repo ID; `baseurl` указывает на наш loopback HTTP. Метаданные `repomd.xml` и связанные файлы образуют согласованный Snapshot.
- `includepkgs` ограничивает видимость разрешённых имён только в нашем repo, но не заменяет **фильтрацию до публикации**: пользователь может менять локальные настройки или опции DNF.
- `priority` проверяется на конкретной версии DNF; меньшее число = более предпочтительный источник. Не считать policy из нашей БД достаточной.
- Два независимых признака: `repo_gpgcheck` (метаданные) и пакетный `gpgcheck`/`pkg_gpgcheck`. DNF4 и DNF5 отличаются настройками; читать эффективную глобальную политику.
- Подписанный издателем RPM: native signature verification при прочих успешных проверках.
- Неподписанный, но attestated RPM: допустим **только** если явная политика администратора и требования ОС разрешают; никогда не менять глобальный `_pkgverify_level` ради Pakomichi.
- Установленный из COPR NetWatch не переключать автоматически на GitHub static RPM, даже при большей версии Git. `build_variant` может быть unknown, и это не доказательство эквивалентности.
- Определение источника установленного RPM должно опираться на реальные данные менеджера; при недостоверности статус unknown.

`R-001`: конфликты и приоритеты. `R-002`: проверки подписи. Тесты DNF4/DNF5 проводить изолированно; не устанавливать неподписанные пакеты на production ради теста.
