# Контракт APT

[English](../../en/specifications/apt.md) · **Русский**

## Выходы адаптера

- Для каждого активного логического источника — принадлежащий Pakomichi `.sources`/`.list` файл (по возможности современный deb822), уникальные поля `Origin`, `Label`, `Suite`, заданный `Signed-By` на *наш* keyring; не использовать глобальный `apt-key`/`trusted=yes`. У каждого уровня происхождения источника свой логический репозиторий с отдельными `Label`/`Origin`, чтобы `apt policy` показывал уровень (ADR-027).
- Подписанный `InRelease` (при необходимости `Release.gpg`), `Packages`/`Packages.gz`, корректные поля checksums/architectures и временная валидность `Valid-Until`, равная подтверждённой свежести.
- `Acquire-By-Hash: yes` обязателен, и каждый индекс выдаётся по своему пути `by-hash`. Изменяемы только `InRelease`, `Release`, `Release.gpg` и простые пути индексов для совместимости, и они выдаются только из текущего поколения (ADR-024).
- **Изначально низкий приоритет** Git-источника. Для каждого активированного имени, включая каждого члена активированного семейства, — адресное предпочтение с `Pin-Priority: 990`, сопоставленное через `Pin: release o=…,l=…` логического репозитория источника (пункт 3 ADR-022) и сверяемое `apt-cache policy`. `Pin: origin` не используется, потому что все логические репозитории обслуживаются с одного loopback-хоста; приоритет 1000 и выше никогда не записывается, потому что он разрешает понижение версии.

## Ограничения

- `apt_preferences` выбирает **версию**, а не экземпляр одинаковой версии из нескольких URL. APT 2.6 сливает равные версии, и решает порядок источников; APT 2.8+ привязывает экземпляр только при новой установке. Равная версия с разными байтами — `E_SOURCE_AMBIGUOUS` на любой версии APT, и никакой pin не заявляется как обеспечивающий origin safety (R-001, пункт 1 ADR-022).
- Активированное имя сохраняет издателя, когда другой источник, в том числе обновление безопасности дистрибутива, позже предлагает более высокую версию; Pakomichi показывает уведомление, а смена — явное решение пользователя (ADR-022).
- Артефакт, чей `Provides` или `Replaces` называет элемент системного пространства имён, удерживается при допуске (`E_SYSTEM_PACKAGE_CONFLICT`, пункт 2 ADR-022); сам APT принимает сторонний `Provides` библиотеки C (R-001 N-008/N-009).
- Не переименовывать и не модифицировать чужие пакеты; не менять файлы чужих APT-репозиториев и глобальную политику. Никогда не требовать `APT::Get::EnableUpgrade`.
- Двоичное совпадение SHA двух *доступных файлов* может свидетельствовать об эквивалентности содержимого; требуется реально доказанный SHA, не только имя/версия.
- Активация — после чтения инвентаризации `dpkg`, репозиториев и проверенной симуляции транзакции `apt-get -s`, с пониманием ограничений этой симуляции.
- При неисполнимом режиме preferred оставить `observing`/`held`. Не изменять исходную версию пакета ради pin.
- `apt-get update` завершается с кодом 0, когда источник недоступен; здоровье источника берётся из собственного состояния Pakomichi, никогда из этого кода выхода (пункт 6 ADR-022).
- `/var/lib/apt/lists` и `/var/cache/apt/archives` никогда не являются доверенным входом (пункт 7 ADR-025).

## Обычная команда обновления

`apt upgrade` и `apt full-upgrade` в Debian и Ubuntu; `apt-get dist-upgrade` в Astra Linux, которая отклоняет `apt upgrade` и `apt-get upgrade` (R-001). Защиту выше нужно показать для каждой перечисленной команды (пункт 4 ADR-022).

## Astra Linux

Поддерживаемый уровень в 0.1 — `base(orel)` на Astra Linux 1.8.6 (ADR-026). Уровень безопасности, замкнутая программная среда и контроль целостности определяются без root; пока замкнутая среда включена или её нельзя исключить, активация отклоняется, а каждый артефакт удерживается с кодом `E_EXECUTION_POLICY` (ADR-025). Applier работает на уровне целостности 63 (служба systemd или сеанс администратора); неудачное применение с более низкого уровня сообщается как проблема уровня целостности (`E_SECURITY_CONTEXT`).

## Испытания

Только на сборках, допущенных ADR-026; первые цели APT — Debian 12 и Astra Linux 1.8.6 на `base(orel)`. Два `.deb` с одной версией и разными sha, перестановка order и Pin-Priority, выбранное семейство (main/service), более высокая версия активированного имени из другого источника при каждой обычной команде обновления, сопоставление `Pin: release` на одном loopback-хосте, обновление системной зависимости, пропажа local server, Valid-Until, повтор более старого поколения.
