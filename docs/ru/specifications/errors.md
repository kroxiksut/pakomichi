# Машинные коды причин и ошибок

[English](../../en/specifications/errors.md) · **Русский**

| Код | Значение | Поведение |
|---|---|---|
| `E_REPO_ID_CHANGED` | По URL другой постоянный repo ID | Suspend, не следовать |
| `E_OWNER_TRANSFER` | Владелец сменился | Suspend до подтверждения |
| `E_ASSET_MUTATED` | Уже принятый артефакт изменился | Reject новой копии, не перепривязывать digest |
| `E_ATTESTATION_INVALID` | Проверка доказательства происхождения провалилась | Reject |
| `E_SIGNATURE_POLICY` | Системная политика требует недоступную RPM-подпись, или неподписанный RPM не выполняет всех условий исключения Attested (ADR-023) | Hold |
| `E_FAMILY_UNAPPROVED` | Новое имя пакета вне разрешённого семейства | Hold |
| `E_SYSTEM_PACKAGE_CONFLICT` | Попытка вытеснить системный пакет/критический `Provides` | Hold |
| `E_SOURCE_AMBIGUOUS` | Одинаковая версия из источников с разными байтами | Observing/hold |
| `E_DEPENDENCY_UNSATISFIABLE` | Требуемые зависимости отсутствуют | Hold |
| `E_PLATFORM_UNSUPPORTED` | Формат/arch/ABI явно не подходит, или системная SQLite старше 3.34.1 (ADR-020) | Hold; для SQLite владелец состояния не запускается |
| `E_SNAPSHOT_INCONSISTENT` | Индекс/ссылка/подпись снимка расходится, в том числе не прошла проверка нашего подписанного `InRelease`/`repomd.xml` (шлюз метаданных, ADR-023) | Не публиковать; сбой подписи сразу после переключения поколения RPM сначала повторяется (ADR-024) |
| `E_CACHE_DIGEST_MISMATCH` | Байты кеша не соответствуют принятому SHA | Не отдавать |
| `E_SOURCE_STALE` | Данные превысили допустимую свежесть | Ошибка нашего источника. В DNF устаревшее поколение заменяет подписанное пустое поколение (ADR-024); в APT истекает `Valid-Until` |
| `E_FORGE_UNAVAILABLE` | Git недоступен | Проверенный кеш по политике |
| `E_ADMIN_APPLY_FAILED` | Неполная запись локальной конфигурации, или эффективные значения, перечитанные после записи, отличаются от записанных | Rollback/reconcile |
| `E_DISK_EXHAUSTED` | Невозможно закончить снимок/загрузку | Отказ новой публикации, старый снимок не менять |
| `E_ARTIFACT_MALFORMED` | Пакет из источника не прошёл структурную инспекцию: обрезанный или повреждённый архив, некорректные заголовки или метаданные, версия формата или сжатие члена, которые не принимает ни один современный `dpkg`/`rpm`, член сверх пределов инспекции или вообще не DEB/RPM | Reject этих байтов; пользователь сообщает издателю о сломанном asset. Корректный пакет, который не может прочитать только штатный инструмент этой системы, — `E_PLATFORM_UNSUPPORTED` |
| `E_EVIDENCE_DOWNGRADE` | Выпуск несёт более слабое доказательство происхождения, чем нижняя граница доверия источника, например нет attestation после выпусков с attestation | Hold выпуска до решения пользователя; граница никогда не понижается автоматически. Пользователь просит издателя вернуть доказательство или, если для источника дано согласие на Pinned, явно одобряет выпуск |
| `E_RELEASE_APPROVAL_REQUIRED` | Выпуск, допускаемый только на уровне Pinned (явное согласие для источника, без криптографического происхождения), ждёт ручного одобрения пользователем этого выпуска | Hold до одобрения выпуска пользователем; одобрение покрывает только просмотренные digest |
| `E_EXECUTION_POLICY` | Политика контроля исполнения ОС не даст запустить исполняемые файлы пакета — например, замкнутая программная среда, запускающая только файлы, подписанные через цепочку ключей производителя ОС (выявлено на Astra Linux, R-006); также если такая политика настроена, но ещё не действует, или её состояние нельзя прочитать | Удерживать все артефакты и не активировать источники; никогда не подписывать, не переподписывать и не изменять файлы, не добавлять ключи и не менять политику. Падение программы под такой политикой сообщается как вероятный отказ политики, а не дефект пакета |
| `E_SECURITY_CONTEXT` | Операция выполняется в контексте безопасности, в котором её нельзя выполнить, — например, уровень целостности или мандатная метка ниже необходимых для записи конфигурации пакетного менеджера (выявлено на Astra Linux, R-006) | Отклонить или откатить применение; сообщить контекст и как повторить из правильного (служба systemd или сеанс администратора); это не ошибка пакета |
| `E_CHANNEL_UNCLEAR` | Релиз, помеченный поставщиком как стабильный, называет предрелиз в теге или в нативной версии (например, тег `10.4.0.0p1-Preview` при `prerelease: false`) | Не предлагается на канале stable и никогда не считается стабильным автоматически; пользователь ждёт стабильного релиза или выбирает следить за предрелизами этого источника |
| `E_SYSTEM_NAMESPACE_UNKNOWN` | Системное пространство имён нельзя вычислить: штатных метаданных включённого источника дистрибутива нет или их нельзя прочитать (до первого `apt update` или `dnf makecache`, после `dnf clean all`, повреждённые списки) | Удерживать новые допуски; опубликованное поколение остаётся как есть; `pchi doctor` называет источник и команду, обновляющую его метаданные. Pakomichi сам штатные метаданные никогда не обновляет |

`Reason` содержит человекочитаемую причину и соответствующий source/package/release ID; чувствительные сведения из сети/ключи не логировать.

## Wire contract v1

Каждая причина передаётся как событие с явной версией схемы:

```json
{
  "schema_version": 1,
  "event": "reason",
  "reason": {
    "code": "E_REPO_ID_CHANGED",
    "object": {
      "kind": "source",
      "id": "source-1234"
    },
    "message": "repository identity changed"
  }
}
```

Версия `1` допускает `object.kind`: `source`, `package`, `release`, `artifact`,
`snapshot`, `operation`, `cache`, `platform`. Неизвестная версия, неизвестное
поле или неизвестное enum-значение отклоняются. `object.id` — ограниченный
идентификатор, а не URL. Человекочитаемый `message` создаётся только через
валидируемый тип: управляющие символы и распространённые формы credentials
отклоняются до сериализации и при десериализации. Формы распознаются по
структуре, а не по отдельному слову: присваивания и заголовки (`token=`,
`password:`, `Authorization:`), строки armor (`-----BEGIN …`), токены с
префиксом и реалистичной длиной (`ghp_…`, `github_pat_…`, `xox…`, `AKIA…`) и
любая userinfo-часть URL (`https://user@host`). Поэтому имена вроде
`slovakia-maps` и фразы о ключе подписи допустимы.

CLI отображает ту же причину без отдельной модели:

```text
[E_REPO_ID_CHANGED] source source-1234: repository identity changed
```

Запрет сигнатур чувствительных данных дополняет очистку на границе сетевых и
криптографических адаптеров, но не заменяет её: произвольную входную ошибку
нельзя напрямую превращать в `message`.

## Wire contract v2: подкоды аттестаций

Версия `2` (п. 7 ADR-030, ADR-031) — это версия 1 плюс `reason.subcode`. Она
пишется только для `E_ATTESTATION_INVALID` с подкодом; все остальные события,
в том числе `E_ATTESTATION_INVALID` без подкода, остаются версией 1, поэтому
читатель версии 1 продолжает их читать и отвергает только события версии 2.
Читатели этого контракта принимают обе версии. Событие версии 2 без `subcode`,
событие версии 1 с ним, `subcode` при другом коде и неизвестный `subcode`
отвергаются.

```json
{
  "schema_version": 2,
  "event": "reason",
  "reason": {
    "code": "E_ATTESTATION_INVALID",
    "object": {
      "kind": "artifact",
      "id": "artifact-1234"
    },
    "message": "attestation rejected: owner id mismatch",
    "subcode": "owner_id_mismatch"
  }
}
```

`message` отказа аттестации — фиксированный текст для его подкода; значения из
bundle или сертификата в него никогда не попадают. Подкоды:

| Подкод | Значение |
|---|---|
| `bundle_too_large` | Bundle больше 256 КиБ |
| `too_many_bundles` | Больше 16 bundle на один digest |
| `bundle_malformed` | Bundle не разбирается, или в его DSSE-конверте не ровно одна подпись |
| `bundle_unsupported` | Не bundle v0.3, не DSSE, не in-toto, или его отвергают структурные правила библиотеки |
| `signature_invalid` | Подпись DSSE над statement не проходит проверку |
| `artifact_digest_mismatch` | Байты не являются subject подписанного statement |
| `certificate_untrusted` | Сертификат не выстраивается до корня доверия или нарушает профиль сертификата |
| `certificate_time` | Ни удостоверяющий центр, ни сертификат не действительны на проверенное время |
| `sct_invalid` | SCT сертификата не проходит проверку |
| `tlog_inclusion` | Доказательство включения в журнал прозрачности не проходит, или проверка журнала неполна |
| `tlog_checkpoint` | Подписанная контрольная точка не проходит проверку |
| `tlog_promise` | Обещание включения или время интеграции не проходят проверку |
| `tlog_entry` | Запись журнала не описывает этот bundle, повреждена или из неизвестного журнала |
| `timestamp_invalid` | Метка времени RFC 3161 не проходит проверку |
| `no_verified_time` | Не проверено ни одного времени подписи |
| `identity_mismatch` | SAN сертификата или OIDC issuer не тот, что требуется |
| `repository_id_mismatch` | Указанный в аттестации ID репозитория не закреплённый |
| `owner_id_mismatch` | Указанный в аттестации ID владельца не из подтверждённых |
| `release_mismatch` | Другие ID релиза, ID пакета, тег или объект ссылки на тег |
| `subject_mismatch` | Имени файла релиза нет или у него другой digest |
| `workflow_mismatch` | Подписант — не закреплённый workflow исходного репозитория |
| `ref_mismatch` | Ref источника не тот, что ожидался |
| `commit_mismatch` | Коммит источника — не тот, на который указывает тег релиза |
| `runner_not_hosted` | Сборка не на runner GitHub |
| `statement_invalid` | Проверенный statement — не in-toto Statement v1 или в нём нет обязательного поля |
| `trust_root_invalid` | Дефект самого корня доверия, например нет ключей CT-журналов |
