# Матрица проверяемых платформ

[English](../../en/testing/matrix.md) · **Русский**

Это план испытаний, а не заявление о поддержке. В итоговой альфе перечислить **только реально проверенные** комбинации. Допуск сборки к заявлению 0.1 — по ADR-026: на этой конкретной сборке матрица выбора R-001; для RPM — матрица R-002; подмножество доставки R-004 (socket activation, поколения с штатными клиентами, сторонние репозитории и удаление) на VM с настоящим systemd и штатным для дистрибутива режимом SELinux или AppArmor; записанная версия SQLite и пройденные тесты миграций (ADR-020); E2E-01 или E2E-02 и применимые N-тесты с собственным пакетом Pakomichi.

Версию систем `bookworm/trixie/...` не выводить из названия машины; сохранять `os-release`, `uname -a`, версии managers и список sources. Для socket activation требуется среда с настоящим systemd, не произвольный контейнер без init. Каждое правило выбора проверяется на каждой сборке дистрибутива, а не выводится из версии менеджера.

## Для каждого стенда

- Fresh snapshot VM, тестовые локальные repos и лабораторные ключи.
- Изоляция `dpkg/rpm` состояния от production.
- Режим SELinux/AppArmor, а на Astra Linux — уровень защищённости, состояние замкнутой программной среды и контроль целостности.
- Логи команд: `apt-cache policy`, `apt-get -s`, `dnf repolist`, фактические SHA downloaded artifacts, подпись репозитория.
- Негативные случаи: совпадение версий, GPG отказ, stale snapshot, поведение offline.
- PASS/FAIL/INCONCLUSIVE с причиной, ссылки на R-отчёт.
