# ADR-011 — One local repository-metadata key per installation

**English** · [Русский](../../ru/decisions/ADR-011.md)

**Status:** accepted as a design decision (concept); operational properties are verified by research tasks.  
**Date:** 2026-10-18.

## Context

This reduces operational complexity; the central key becomes the trusted authority of the local system and requires backup/rotation.

## Decision

For 0.1, use a separate local key with strict permissions to sign all our logical repos; each repo has its own provenance policy. The key does not sign DEB/RPM as a publisher.

## Alternatives and reasons for rejection

One key per Git repository without an operational need / privileges for the downloader — deferred/rejected.

## Consequences and constraints

This decision is mandatory for the design of the API, state, and tests. If a specific OS version does not provide the specified behavior, support for that combination must not be declared without restricting functionality. Any change to this decision requires a new superseding ADR and confirmation by the project owner.

## Verification

R-002/R-004 verify trust in local metadata and key loss/rotation.
