# ADR-007 — One HTTP service, many logical repositories

**English** · [Русский](../../ru/decisions/ADR-007.md)

**Status:** accepted as a design decision (concept); operational properties are verified by research tasks.  
**Date:** 2026-10-18.

## Context

Packages can be fetched on demand without keeping a permanently running process. `file://` without prefetching cannot provide lazy downloading.

## Decision

By default: loopback HTTP with systemd socket activation, one process/cache, and separate signed metadata endpoints for each source. The control API is a separate local IPC.

## Alternatives and reasons for rejection

A single logical repository for all Git sources / a permanent service as the only option / file-only as the primary path — not chosen.

## Consequences and constraints

This decision is mandatory for the design of the API, state, and tests. If a specific OS version does not provide the specified behavior, support for that combination must not be declared without restricting functionality. Any change to this decision requires a new superseding ADR and confirmation by the project owner.

## Verification

R-004 verifies operation under parallel requests and failures; the fallback is an ordinary systemd service.
