# ADR-002 — System package families from one Git project

**English** · [Русский](../../ru/decisions/ADR-002.md)

**Status:** accepted as a design decision (concept); operational properties are verified by research tasks.  
**Date:** 2026-10-18.

## Context

One application may consist of a CLI/service/shared part. Family membership is confirmed by the user, not by a prefix wildcard.

## Decision

One repo may contain several allowed families/names of `.deb`/`.rpm` from one CI and one codebase. New versions of an allowed name are verified automatically; new names require extending the allowlist.

## Alternatives and reasons for rejection

One repo = one package — rejected; trusting any new `.deb` from the author — rejected.

## Consequences and constraints

This decision is mandatory for the design of the API, state, and tests. If a specific OS version does not provide the specified behavior, support for that combination must not be declared without restricting functionality. Any change to this decision requires a new superseding ADR and confirmation by the project owner.

## Verification

Acceptance criteria: R-001/e2e family upgrade; a Provides/Obsoletes conflict and a new package are held.
