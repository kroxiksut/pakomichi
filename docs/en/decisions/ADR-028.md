# ADR-028 — DEB metadata through `dpkg-deb --ctrl-tarfile`

**English** · [Русский](../../ru/decisions/ADR-028.md)

**Status:** accepted by the project owner on 2026-10-20; supersedes point 4 of ADR-017 in part (the `dpkg-deb` mode used to read DEB metadata). The rest of point 4 and all other points of ADR-017 remain in force.  
**Date:** 2026-10-20.

## Context

ADR-017 point 4 selects `dpkg-deb --field/--info` for DEB metadata behind an unprivileged, resource-limited inspector process, and forbids invoking install, unpack, or maintainer scripts during inspection. The P0-004 prototype used those modes. The inspector implemented in `src/inspect/` (`runner.rs`, `deb.rs`, `ar.rs`, `tar.rs`, `control.rs`) instead streams the control archive with `dpkg-deb --ctrl-tarfile` and parses it in memory, as described in [`architecture/privileges.md`](../architecture/privileges.md), "Package inspector boundary (DEB)". In that form `dpkg-deb` only decompresses the control member; every check on the content is made by Pakomichi's own bounded parsers, so the limits do not depend on how `dpkg-deb` parses or formats a control file.

## Decision

1. DEB metadata is read with `dpkg-deb --ctrl-tarfile`, not with `--field` or `--info`.
2. Before any decompression the inspector checks, in-process, a file opened with `O_NOFOLLOW` that must be a regular file: the package size limit, then the outer `ar` container (member order, `debian-binary` major version 2, the control and data member names, the compressed control member size, and the end of every member within the file).
3. `dpkg-deb` runs in a child process without a shell, under `prlimit` (`--cpu`, `--as`, `--fsize=0`, `--core=0`, `--nofile`), with `PATH=/usr/bin:/bin` and `LC_ALL=C` as its only environment, `/` as its working directory, and the checked package as its standard input (`/proc/self/fd/0`). Both tools are taken from `/usr/bin` or `/bin` only. The parent enforces a wall-clock timeout and caps the decompressed control stream and the diagnostics, and kills the child when a limit is exceeded. Without `prlimit` the inspector refuses to run unless the configuration explicitly allows it.
4. The control archive goes into a pipe under the inspector's size cap and is parsed in memory: a minimal tar reader lists it and copies out `control` (duplicate or non-regular `control` entries, absolute names, and `..` components are rejected), and a strict deb822 parser reads the paragraph. Maintainer scripts are only reported as present. Nothing is written to disk.
5. Unchanged from ADR-017 point 4: the inspector is unprivileged (it refuses effective UID 0; the override exists for tests only) and never invokes `dpkg`, `dpkg-deb --extract`/`--install`/`--control`, `tar -x`, or a maintainer script.

## Alternatives and reasons for rejection

- **`dpkg-deb --field`/`--info` (ADR-017 point 4):** the checks on the control content would then depend on `dpkg-deb`'s own parsing and output formatting rather than on Pakomichi's strict, bounded parsers (duplicate fields, control characters, size and count limits). Superseded.
- **`dpkg-deb --control` into a directory:** extracts files to disk; contradicts the no-write rule of the inspector.
- **A pure in-process decompressor for every control compression:** removes the native tool, but adds decompression code for each compressor to the parser process; not needed while `dpkg-deb` under `prlimit` does only that step.

## Consequences

- `architecture/privileges.md` already describes this method; `docs/en/prototypes/P0-004-stack.md` keeps the historical `--field/--info` evidence of the prototype.
- A package that fails structural inspection gets the reason code `E_ARTIFACT_MALFORMED` (`specifications/errors.md`, `ReasonCode`). A `dpkg-deb` refusal of a member compression that the system's `dpkg` does not support stays `E_PLATFORM_UNSUPPORTED`, because the package may be well-formed. `src/inspect/error.rs` and `architecture/privileges.md` follow this mapping.
- Process isolation beyond these limits (a dedicated user, a systemd sandbox, seccomp) remains a deployment concern of the inspector unit.

## Verification

- Implementation and tests: `src/inspect/runner.rs`, `src/inspect/runner_tests.rs`, and the parser tests in `src/inspect/`, run by `scripts/quality.ps1` (the `dpkg-deb` path runs on Linux only).
- N-020 (malicious malformed DEB): no installation script runs, limits hold, the process is not root.
