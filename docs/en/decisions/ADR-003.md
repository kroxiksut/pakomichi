# ADR-003 — Do not deliver system dependencies from third-party Git

**English** · [Русский](../../ru/decisions/ADR-003.md)

**Status:** accepted as a design decision (concept); operational properties are verified by research tasks.  
**Date:** 2026-10-18.

## Context

We prohibit partial distribution migration and do not become a system solver. Full safety of future transactions is not guaranteed without control over third-party repositories.

## Decision

Pakomichi provides only allowed application packages/components. Dependencies are resolved by the native package manager from already configured sources; we do not publish explicitly incompatible builds. Do not create global APT/DNF hooks.

## Alternatives and reasons for rejection

Automatic Git dependency discovery / replacing glibc from the next distribution release / a global apt hook — rejected.

## Consequences and constraints

This decision is mandatory for the design of the API, state, and tests. If a specific OS version does not provide the specified behavior, support for that combination must not be declared without restricting functionality. Any change to this decision requires a new superseding ADR and confirmation by the project owner.

## Verification

R-001 verifies real transactions, including dependencies and downgrade scenarios.
