# ADR-001 — Pinning a specific Git repository

**English** · [Русский](../../ru/decisions/ADR-001.md)

**Status:** accepted as a design decision (concept); operational properties are verified by research tasks.  
**Date:** 2026-10-18.

## Context

A URL may be reassigned to a new repository; forks and the author's other repositories do not inherit trust.

## Decision

Source identity is `(forge, stable repository_id)` plus `owner_id` and the canonical URL history. Updates come only from that source; a rename with the same IDs is permissible after verification; an owner transfer requires confirmation.

## Alternatives and reasons for rejection

By URL and project name / searching for the freshest fork — rejected; a Git commit alone as the key — insufficient for pinning the publisher.

## Consequences and constraints

This decision is mandatory for the design of the API, state, and tests. If a specific OS version does not provide the specified behavior, support for that combination must not be declared without restricting functionality. Any change to this decision requires a new superseding ADR and confirmation by the project owner.

## Verification

R-003 verifies sourceRepositoryIdentifier comparison, owner transfers, and same-name recreation.
