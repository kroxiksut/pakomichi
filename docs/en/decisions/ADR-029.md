# ADR-029 — Local IPC: Unix sockets per channel and length-prefixed JSON

**English** · [Русский](../../ru/decisions/ADR-029.md)

**Status:** accepted by the project owner on 2026-10-21. It refines ADR-009 and ADR-017 point 7 and supersedes none. ADR-019 point 2 applies to every message defined here. The last sentence of point 5 is superseded by ADR-031.  
**Date:** 2026-10-21.

## Context

ADR-017 point 7 splits Pakomichi into an unprivileged core and state owner, a disposable package inspector, a read-only repository reader, a metadata signer, and a narrowly privileged administrative applier, and makes IPC messages and filesystem ownership the authority boundary. ADR-009 requires a read-only status API and a privileged helper that applies only Pakomichi's own files. `specifications/cli-api.md` requires that consent, release approval, and socket recovery are administrative and interactive, never reachable through the status API, the loopback HTTP endpoint, or `--yes`. ADR-019 point 2 requires an explicit `schema_version`, rejection of unknown fields, and conversion into validated domain types for every format Pakomichi owns. The transport and the framing were left open (`architecture/overview.md`, "Undetermined details").

Pakomichi runs only on Linux with systemd (ADR-014, ADR-026). The known failure classes of a local service protocol that this decision has to exclude are: an authority decision taken from a field of the request; a liveness check queued behind a long operation, so that "busy" reads as "dead"; operation identifiers that can be guessed; an absent field silently meaning "off" for a protection; one default declared on both sides of the wire and drifting apart; serialization attributes renaming something other than the author expected; and a response truncated because the stream was closed before it was flushed.

## Decision

1. **Transport.** Local IPC uses Unix domain stream sockets created by systemd socket units in `/run/pakomichi/` (`RuntimeDirectory`, mode 0755, owned by root). The processes receive them already bound; there is no fallback bind. No IPC socket is ever a TCP socket, and no Pakomichi IPC is reachable from the network.
2. **One socket per channel; the channel decides the authority.**

   | Socket | Mode and owner | Accepted peers | Accepted requests |
   |---|---|---|---|
   | `/run/pakomichi/status.sock` | 0666, root | any local user | read-only requests only |
   | `/run/pakomichi/admin.sock` | 0600, root | uid 0 only | read-only and administrative requests |
   | `/run/pakomichi/apply.sock` | 0600, the state owner's system user | the uid of the state owner only | applier requests from the state owner |

   - The listening process inherits the socket from systemd, so the file owner decides only who may connect: the state owner serves `status.sock` and `admin.sock`, and the root applier serves `apply.sock`, which the unprivileged state owner must be able to open.
   - The server reads `SO_PEERCRED` (uid, gid, pid) on every accepted connection and checks the uid against the table before it reads the first frame; a mismatch closes the connection without a response. The file mode is a second barrier, not the only one.
   - Administrative requests require root (`sudo pchi …`), as `apt` and `dnf` do. A delegated administrators' group is not part of 0.1: `SO_PEERCRED` carries only the primary gid, so a group check needs a separate design and a superseding decision.
   - Each channel has its own request type in code. The status channel's type has no administrative variant, so an administrative request on it fails to parse as an unknown variant; the server never selects a check from a field of the request. Which checks a request needs is computed by the server from the request type and the channel.
3. **Child processes.** The package inspector and the signer are child processes of the state owner and talk to it over their standard input and output with the same framing and message rules. The inspector handles exactly one request per process (ADR-017). The signer handles one signing request per invocation in 0.1. Standard error carries diagnostics only and is capped as for the inspector today.
4. **Framing.** Every message is one frame: a 4-byte big-endian unsigned length followed by exactly that many bytes of UTF-8 JSON. A request frame is at most 1 MiB, a response frame at most 8 MiB. A length over the limit, a zero length, a truncated frame, or invalid UTF-8 closes the connection without parsing. One request is in flight per connection; a client that needs parallel work opens more connections.
5. **Messages.** Every message is a JSON object with `schema_version` (1 for this protocol) and a `type`. The wire types use `#[serde(deny_unknown_fields)]` and are converted into validated domain types (ADR-019). An unknown `schema_version` is answered with an error naming the supported versions, and the connection is closed. An unknown field, an unknown `type`, or a mistyped value is answered with an error and no part of the request is applied. Reason events inside responses keep the wire contract v1 of `specifications/errors.md`.
   - A field that disables, weakens, or confirms a protection has no default: it is required, and a request without it is refused. A partial update names the fields it changes; a full replacement must carry all of them.
   - A default that both sides need is defined once, in the Rust protocol module, and the CLI uses that module; no second copy exists.
6. **Liveness.** `ping` is answered by the accept loop of each channel without entering the queue of work, within a short deadline. Long administrative work is never performed inside a request: the request starts an operation and returns its identifier at once, and progress is read with status requests. A liveness timeout therefore means that the server does not answer, not that it is busy.
7. **Operation identifiers.** An operation identifier is 128 bits from the operating system's cryptographic random source, encoded as 32 lowercase hexadecimal characters, and is bound to the uid that started the operation. Reading or cancelling an operation requires the same uid or uid 0; an unknown identifier and a foreign one get the same answer. An identifier never grants authority by itself.
8. **Confirmation of administrative actions.** The CLI shows the plan and asks the administrator interactively (`cli-api.md`). The server first returns the plan with a digest of its exact content; the confirming request must carry `confirmed: true` and that digest, and is accepted only on `admin.sock`. A plan that changed in between is refused. The server cannot prove that a human answered; it guarantees that confirmation comes only from root on the administrative channel and only for the plan that was shown. `--yes` never sets it for the actions that `cli-api.md` excludes.
9. **Deadlines and limits.** On `status.sock`: the first frame must arrive within 5 seconds of accepting (shorter than the 10 seconds R-004 used for slow HTTP clients), an idle connection is closed after 30 seconds, at most 8 concurrent connections per uid and 64 in total; connections over the limit are closed at once. On `admin.sock` and `apply.sock`: at most 4 concurrent connections. These values are fixed and tested by P2-013; a change is recorded with its test, as ADR-024 point 5 requires for the HTTP reader.
10. **Closing.** A server writes the whole response frame, flushes it, shuts down its write side, and only then closes the socket. A client reads until the end of the response frame. A response is never written after the connection was half-closed by the server.

## Alternatives and reasons for rejection

- **D-Bus (system bus):** policy files for the bus daemon, a second authority model next to the socket modes, and a large dependency for a protocol with three clients. Right when a desktop integration or other programs must call the service; not needed for 0.1.
- **gRPC or protobuf over a socket:** a code generator and a schema language beside serde, and HTTP/2 framing for a local request-response protocol. Right when clients in many languages must use the API; ours are the Rust CLI and Pakomichi's own processes.
- **One socket with a role field or a token in the request:** the authority would come from the request itself. Refused.
- **Newline-delimited JSON:** simple, but the size is known only after reading, and a message without a newline grows until a limit hits. Length-prefixed frames refuse an oversized message before reading it.
- **Varlink:** a fitting model, but an additional protocol and library for the same guarantees as the framing above.
- **An administrators' group on `admin.sock` (mode 0660):** convenient, but needs a supplementary-group check that `SO_PEERCRED` does not provide, and makes group membership root-equivalent for Pakomichi's files. Deferred.

## Consequences

- Every administrative command needs `sudo`; the status commands do not.
- The protocol module is shared by the CLI and the server, so the CLI is written in Rust and links the same message types.
- P2-013 implements the sockets, the framing, the per-channel request types, the peer checks, the limits, the liveness path, the operation identifiers, the plan digest, and the child-process channels; it adds a stable reason code for a refused protocol message if the existing codes do not cover it (ADR-019 point 2), with the owner's approval.
- The systemd units of P5-004a carry the socket paths, modes, and owners of point 2.
- `architecture/overview.md` no longer lists the IPC format as undetermined.

## Verification

- Required tests in P2-013: a peer with the wrong uid is refused on each socket; an administrative request on `status.sock` is refused as unknown; frames over the limit, zero-length, truncated, and non-UTF-8 frames close the connection without parsing; an unknown `schema_version`, field, or `type` is refused and nothing is applied; a request without a required protection field is refused; a wire-shape test pins the exact JSON of every request and response variant; `ping` answers within its deadline while a long operation runs; a foreign or unknown operation identifier gets the same refusal; a confirmation with a stale plan digest is refused; a slow client is cut at the first-frame deadline and the per-uid limit holds; a response is fully read by the client after the server closes.
- The socket modes and owners are verified on a VM with the real systemd units (P5-001, P5-004b). None of these tests exists yet.
