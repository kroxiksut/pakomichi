# ADR-006 — RPM signatures and attestations as separate boundaries

**English** · [Русский](../../ru/decisions/ADR-006.md)

**Status:** accepted as a design decision (concept); operational properties are verified by research tasks.  
**Date:** 2026-10-18.

## Context

repo_gpgcheck != pkg_gpgcheck. The DNF4/DNF5 difference and an enforced system policy require an adapter.

## Decision

The local repo signer signs metadata. An RPM with a publisher signature is verified natively. Pakomichi publishes an unsigned attested RPM only if the policy of the specific repository explicitly permits it and a mandatory system package check does not prohibit it. Do not re-sign RPMs.

## Alternatives and reasons for rejection

Re-signing third-party RPMs / global gpgcheck=0 / treating a GitHub attestation as an embedded GPG signature — rejected.

## Consequences and constraints

This decision is mandatory for the design of the API, state, and tests. If a specific OS version does not provide the specified behavior, support for that combination must not be declared without restricting functionality. Any change to this decision requires a new superseding ADR and confirmation by the project owner.

## Verification

R-002 builds an allow/block matrix on DNF4, DNF5, and an enforced RPM policy.
