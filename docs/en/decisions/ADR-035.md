# ADR-035 — Process layout: isolated signer and inspector, a lazy-fetch channel for the reader

**English** · [Русский](../../ru/decisions/ADR-035.md)

**Status:** accepted by the project owner on 2026-10-23. It refines ADR-017 point 7 and ADR-029 points 2 and 3 and supersedes nothing.  
**Date:** 2026-10-23.

## Context

ADR-017 point 7 splits Pakomichi into an unprivileged state owner, a disposable package inspector, a read-only repository reader, a metadata signer, and a root applier. ADR-029 point 3 makes the inspector and the signer child processes of the state owner that talk over standard input and output. Three gaps appeared when the processes were planned (P2-013b):

- A child process runs as the user of its parent. The signer would then run as the state owner's user, and the local metadata key would be readable by the state owner. P2-013b requires the opposite: the private key is readable by nobody but the signer (`architecture/trust.md`, ADR-011).
- The inspector parses untrusted package bytes (ADR-009, ADR-028). Run as the state owner's user, a compromised inspector holds the state database and the CAS.
- The lazy fetch of P3-005b needs the read-only reader to ask the state owner, which owns the CAS writer and the network, for a missing package. ADR-029 point 2 has no channel for that.

## Decision

1. **Signer and inspector are systemd socket services with `Accept=yes`.** systemd starts one service instance per connection and passes the connection as the instance's standard input and output, so the framing and message rules of ADR-029 points 3–5 stay unchanged, and every request still gets a fresh process.
   - **Signer:** a dedicated system user `pakomichi-signer`; the metadata key lives in its own state directory, mode 0700, and no other Pakomichi user can read it. One signing request per instance.
   - **Inspector:** `DynamicUser=yes`, no network (`PrivateNetwork=yes`, `RestrictAddressFamilies=AF_UNIX`), a read-only file system, the resource limits of ADR-017 point 4; the package arrives on standard input. One inspection per instance.
2. **Sockets added to the table of ADR-029 point 2:**

   | Socket | Mode and owner | Accepted peers | Accepted requests | Served by |
   |---|---|---|---|---|
   | `/run/pakomichi/sign.sock` | 0600, the state owner's user | the state owner's uid | one signing request | signer instance |
   | `/run/pakomichi/inspect.sock` | 0600, the state owner's user | the state owner's uid | one inspection request | inspector instance |
   | `/run/pakomichi/fetch.sock` | 0600, the reader's user | the reader's uid | fetch requests | state owner |

   Every server checks `SO_PEERCRED` before the first frame, as ADR-029 point 2 requires. An `Accept=yes` instance reads the peer credentials of the connection it was given.
3. **The lazy-fetch channel carries one request type:** fetch the object with this SHA-256 and size. The answer is "stored" or an error with the HTTP status the reader returns (502, 504, 507, 500, `architecture/delivery-recovery.md`). It carries no bytes: the reader opens and hashes the object in the CAS itself before serving it. A digest without a pin is refused by the state owner.
4. **Network access stays in the state owner** (ADR-017 point 1). There is no separate network process in 0.1.

## Alternatives and reasons for rejection

- **Plain child processes of the state owner (ADR-029 point 3 read literally):** simpler, but the key and the parser of untrusted bytes would share the state owner's user. Right where the key and the parser are already confined by other means (a separate container, a hardware token).
- **A setuid helper for the signer:** a second privileged binary for one operation; systemd already provides the user switch.
- **The reader fetches and writes the CAS itself:** the reader would no longer be read-only, against ADR-017 point 7.
- **A separate network process now:** one more channel and process for no gain in 0.1; right when the state owner must run without network access.

## Consequences

- P2-013b implements the three sockets, the peer rules, the `Accept=yes` instances, and the start-up privilege checks; P5-004a ships the units with the modes and owners of point 2.
- `architecture/privileges.md` and `architecture/overview.md` describe the layout; the state owner's signer and inspector calls go through the sockets instead of spawning `gpg` and the inspector itself.
- Signing and inspection cost one process start per request, as before.

## Verification

- Tests in P2-013b: a peer with another uid is refused on each new socket before the first frame; the key file is unreadable to the state owner's user; the inspector instance has no network and cannot write outside its private temporary space; a fetch request for an unpinned digest is refused and nothing is downloaded.
- Modes, owners, and sandboxing are verified on a VM with the real units (P5-001, P5-004b).
