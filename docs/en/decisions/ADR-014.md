# ADR-014 — 0.1 alpha boundaries and explicitly deferred capabilities

**English** · [Русский](../../ru/decisions/ADR-014.md)

**Status:** accepted as a design decision (concept); operational properties are verified by research tasks.  
**Date:** 2026-10-18.

## Context

We verify the core value before expanding platforms; WinGet is to be investigated in parallel, but must not block.

## Decision

0.1: GitHub public Releases, DEB/APT and RPM/DNF4/DNF5, CLI, read-only API, trust/cache/failures. WinGet, GitLab/Gitea/Forgejo, GUI, tar-to-package, community catalog — after alpha.

## Alternatives and reasons for rejection

Including everything in 0.1 / building our own alternative to apt/dnf — rejected.

## Consequences and constraints

This decision is mandatory for the design of the API, state, and tests. If a specific OS version does not provide the specified behavior, support for that combination must not be declared without restricting functionality. Any change to this decision requires a new superseding ADR and confirmation by the project owner.

Criteria in `docs/en/testing/release-gate.md` and boundaries in `docs/en/product/scope-0.1.md`.
