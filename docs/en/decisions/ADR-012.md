# ADR-012 — Native versions and explicit provider migration

**English** · [Русский](../../ru/decisions/ADR-012.md)

**Status:** accepted as a design decision (concept); operational properties are verified by research tasks.  
**Date:** 2026-10-18.

## Context

NetWatch showed two RPMs with the same name but different libpcap dynamic linking and different provenance.

## Decision

The GitHub tag and the native DEB/RPM version are stored separately. Never rewrite NEVRA/version. Migration between COPR/an official repo/GitHub or between build variants is an explicit operation with plan verification.

## Alternatives and reasons for rejection

Treating any greater Git version as an acceptable replacement / changing epoch/release / a hidden fallback to a fork — rejected.

## Consequences and constraints

This decision is mandatory for the design of the API, state, and tests. If a specific OS version does not provide the specified behavior, support for that combination must not be declared without restricting functionality. Any change to this decision requires a new superseding ADR and confirmation by the project owner.

## Verification

R-001 and the NetWatch E2E (without changing a real user system).
