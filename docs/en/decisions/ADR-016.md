# ADR-016 — Separate licenses for code and documentation prose

**English** · [Русский](../../ru/decisions/ADR-016.md)

**Status:** accepted by the project owner; supersedes the documentation portion of the initial licensing decision while preserving its software-license decision.
**Date:** 2026-10-18.

## Context

Pakomichi source code and original documentation were initially offered together under `MIT OR Apache-2.0`. The project is also expected to provide code examples that may later be reused in a commercial book. A documentation-specific Creative Commons license can make prose reuse and attribution clearer, but applying a Creative Commons license to executable or copyable code is undesirable. Using CC BY-SA for prose would additionally require shared adaptations to remain under the same or a compatible license, which complicates editorial reuse without improving the software license.

The boundary must remain clear in mixed Markdown documents that contain both prose and code blocks.

## Decision

- Original source code and code-like material are licensed as `MIT OR Apache-2.0`.
- Original documentation prose and original diagrams are licensed as `CC-BY-4.0`.
- Code-like material includes source files, code blocks, shell commands, configuration examples, schemas, machine-readable examples, test fixtures, and comparable material intended to be copied into or executed as part of software.
- In a mixed Markdown document, CC BY 4.0 applies to original prose and diagrams; `MIT OR Apache-2.0` applies to the embedded code-like portions.
- Incoming contributions follow the same split, with contributors retaining copyright.
- `LICENSING.md` is the authoritative scope statement. `LICENSE-MIT`, `LICENSE-APACHE`, and `LICENSE-DOCS` contain the complete license texts.
- Third-party material retains its own license and notices and must be marked explicitly.

## Alternatives and reasons for rejection

- **Keep documentation under `MIT OR Apache-2.0`.** Legally workable and simple, but less conventional for prose and less explicit about attribution when material moves into articles or books.
- **Use CC BY-SA 4.0 for documentation.** Rejected because adapted material carries ShareAlike obligations that may complicate publisher workflows. Adding BY-SA merely as a third alternative beside MIT and Apache would not reliably preserve ShareAlike because recipients could choose a permissive alternative.
- **Apply CC BY 4.0 to entire Markdown files, including code blocks.** Rejected because Creative Commons licenses are designed for creative works and documentation, not as software licenses. It would also make code copied from documentation differ in licensing from the same code in source files.
- **Require copyright assignment for contributions.** Rejected; the existing contribution model retains contributor copyright and grants the necessary public licenses.

## Consequences and limitations

Future books may reuse documentation prose commercially with CC BY attribution and may reuse code examples under MIT or Apache-2.0. Significant excerpts contributed by others must retain the attribution and notices required by their applicable license. The owner may separately license material for which the owner holds all rights, but cannot unilaterally relicense third-party contributions or external material.

Mixed documents should refer to `LICENSING.md` rather than carrying one SPDX identifier that incorrectly covers every kind of content. Source files continue to use `SPDX-License-Identifier: MIT OR Apache-2.0`; metadata for documentation prose alone may use `CC-BY-4.0`.
