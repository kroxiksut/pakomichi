# ADR-013 — SQLite + verified CAS and transactional application to the OS

**English** · [Русский](../../ru/decisions/ADR-013.md)

**Status:** accepted as a design decision (concept); operational properties are verified by research tasks.  
**Date:** 2026-10-18.

## Context

Bulky packages are not stored in the database; after a crash, the true state can be restored from verified files and the journal.

## Decision

SQLite stores states and decisions; files are stored in content-addressed storage (CAS) by SHA. Applying OS configuration uses an intent journal, staging, rename, verification, and reconcile; do not treat SQLite+FS as one transaction.

## Alternatives and reasons for rejection

Storing blobs in SQLite / arbitrarily restoring trusted sources from the current GitHub API — rejected.

## Consequences and constraints

This decision is mandatory for the design of the API, state, and tests. If a specific OS version does not provide the specified behavior, support for that combination must not be declared without restricting functionality. Any change to this decision requires a new superseding ADR and confirmation by the project owner.

## Verification

R-004 + E2E schema migration, powerloss, disk full, and rollback.
