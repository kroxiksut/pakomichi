# ADR-005 — Two GitHub trust modes: Strict and Attested

**English** · [Русский](../../ru/decisions/ADR-005.md)

**Status:** accepted as a design decision (concept); operational properties are verified by research tasks.  
**Date:** 2026-10-18.

## Context

A significant share of existing Git Releases are not immutable but have attestations; excluding them without technical necessity contradicts the value of the project.

## Decision

Strict: an immutable Release with a verified release attestation. Attested: the release may be mutable, but a cryptographic artifact attestation, the pinned repository ID, and the SHA of the specific bytes are verified. An already accepted record must never be overwritten with a new digest.

## Alternatives and reasons for rejection

Immutable only, GitHub SHA field only, pure TOFU without cryptographic provenance — rejected for the 0.1 automatic mode.

## Consequences and constraints

This decision is mandatory for the design of the API, state, and tests. If a specific OS version does not provide the specified behavior, support for that combination must not be declared without restricting functionality. Any change to this decision requires a new superseding ADR and confirmation by the project owner.

## Verification

R-003 verifies real predicates, embedded repo ID, rename/transfer, and altered mutable assets.
