# ADR-004 — Sources and identical versions: rejecting ambiguous automation

**English** · [Русский](../../ru/decisions/ADR-004.md)

**Status:** accepted as a design decision (concept); operational properties are verified by research tasks.  
**Date:** 2026-10-18.

## Context

An APT pin selects a version; it does not guarantee a specific instance of an equal version. We must not promise more than the package manager is capable of.

## Decision

Each Git source is a separate logical repo; APT `Origin/Label/Suite` and a targeted pin, DNF repo ID/priority/includepkgs. If an identical native version from different sources has different bytes and the selection cannot be proven, the conflicting package is only observing/held.

## Alternatives and reasons for rejection

Changing the native version with a suffix / silently editing third-party sources / relying on the status in our database — rejected.

## Consequences and constraints

This decision is mandatory for the design of the API, state, and tests. If a specific OS version does not provide the specified behavior, support for that combination must not be declared without restricting functionality. Any change to this decision requires a new superseding ADR and confirmation by the project owner.

## Verification

R-001. A mandatory negative test with two identical versions and different sha.
