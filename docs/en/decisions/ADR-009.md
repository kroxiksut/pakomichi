# ADR-009 — Privilege separation and a restricted API

**English** · [Русский](../../ru/decisions/ADR-009.md)

**Status:** accepted as a design decision (concept); operational properties are verified by research tasks.  
**Date:** 2026-10-18.

## Context

Packages from the internet are untrusted bytes; access to the key and the system configuration must be limited to the minimum number of processes.

## Decision

Fetch/inspect/verify run without root; the privileged helper only applies our repo/keyring files; the local signer is protected. HTTP is read-only; the status API is read-only, with no software installation.

## Alternatives and reasons for rejection

Executing maintainer scripts during inspection / running the entire service as root / an open network control API — rejected.

## Consequences and constraints

This decision is mandatory for the design of the API, state, and tests. If a specific OS version does not provide the specified behavior, support for that combination must not be declared without restricting functionality. Any change to this decision requires a new superseding ADR and confirmation by the project owner.

## Verification

Negative tests for untrusted archives, path traversal, SSRF, and IPC permissions.
