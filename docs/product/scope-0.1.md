# Версия 0.1 alpha: объём и явно отложенные функции

## Обязательные возможности

- GitHub Releases **публичных** репозиториев, точная привязка к GitHub repository ID и owner ID.
- DEB/APT (Debian/Ubuntu в испытанной матрице), RPM/DNF4 и DNF5 в испытанных окружениях.
- Подключение конкретного URL, обнаружение пакетов, выбор разрешённого семейства, активация / наблюдение / отключение.
- Два проверяемых способа подтверждения происхождения — Strict (immutable release + подходящая проверка) и Attested (криптографически проверенная attestation конкретного артефакта); поддержка только при подтверждённой реализации R-003.
- Предварительная проверка архитектуры, родных метаданных, зависимостей, конфликтов и установленных источников.
- Подписанные логические локальные репозитории, проверенные поколения снимков, SHA-256/immutable content paths, скачивание по требованию там, где оно допустимо.
- Запрет неоднозначных автоматических переходов, отсутствие автоматического поиска Git-зависимостей и замены системных библиотек.
- Минимальные CLI для source add/inspect/activate/list/sync/diagnose/remove; только read-only статус API.
- Откат неудачной операции изменения конфигурации, автономность установленных программ от удаления Pakomichi.
- Документы по восстановлению, логи причин допусков/отказов, воспроизводимые негативные тесты.

## Не включать в 0.1 alpha

- GitLab/Gitea/Forgejo как реализованные адаптеры (интерфейсы готовим).
- WinGet, GUI, общедоступный веб-каталог, автоматические рекомендации форков.
- Кроссплатформенный пересборщик архивов в нативные системные пакеты.
- Автоматическое восстановление ОС после ошибочной установки чужого приложения; полная изоляция его скриптов установки.
- Автоматические доверенные уведомления об отзыве с собственной инфраструктурой, полную реализацию TUF.
- Автоматическое исполнение установочных команд приложений из локального API.
- Жёсткую гарантию отсутствия вредоносного кода или работоспособности чужого бинарника на любой родственной ОС.

## Блокирующие исследования

`R-001` выбор версий/источников; `R-002` RPM-проверки; `R-003` GitHub attestation/immutable; `R-004` локальная доставка и снимки. Исследования блокируют **только свои зависимые компоненты**; остальные работы могут идти параллельно.

См. `docs/testing/release-gate.md`. Не публиковать обобщённые заявления «работает на всех Debian/Fedora/Astra», если подтверждена лишь часть матрицы.
