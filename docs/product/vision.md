# Продукт: назначение и границы ответственности

## Проблема

Автор прикрепляет валидные `.deb`/`.rpm` в Git Releases, но пользователю приходится вручную скачивать каждый новый файл или добавлять отдельный APT/RPM-репозиторий, которого у автора нет. Создание полноценного подписанного репозитория требует сопровождения индексов, подписи, ключей и публикации.

## Решение

Pakomichi служит **мостом между выбранным Git Release и штатными механизмами пакетных менеджеров**, без замены APT/DNF, без собственного разрешителя системных зависимостей и без требования владельцу каждого проекта поддерживать отдельный репозиторий.

## Кому полезно

1. Пользователь: добавляет конкретный Git URL, получает штатные установки и обновления при успешной проверке.
2. Автор: публикует в Releases как раньше; опционально добавляет CI-описание совместимости/семейств.
3. Администратор: закрепляет источники, проверяет конфликты и поддерживает контролируемые обновления.

## Не является

- Новым пакетным менеджером или удалённым каталогом «всех пакетов GitHub».
- Автоматическим поисковиком форков, зеркал, репозиториев автора или системных зависимостей на GitHub.
- Сервисом оценки репутации разработчиков и вредоносности программы.
- Средством частичной миграции дистрибутива или обновления системных библиотек из произвольных источников.
- Универсальным установщиком архивов и исполняемых файлов.

## Метрики проверки полезности (не придуманные успехи)

- 3 разных внешних проекта с релизными DEB/RPM: минимум 1 без собственного APT/RPM-репозитория.
- Установка и последующее обновление штатными командами на поддержанной Debian-/Fedora-подобной системе.
- 0 несанкционированных смен издателя/пакета в негативных тестах.
- Измерить: время настройки пользователем, объём изменений CI автора, число API-запросов, процент совместимых реальных выпусков, объём кеша.
