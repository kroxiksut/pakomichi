# Операционная процедура программирующего агента

## Начало работы

1. Прочитать `AGENTS.md`, `docs/INDEX.md`, связанную запись в локальном `TASKS_RU.md` и необходимые ADR.
2. Проверить зависимости задачи, результаты R-исследований и состояние ветки. Нельзя считать документ `R-001` самим результатом исследования.
3. Выбрать запись с точным ID из `TASKS_RU.md`; если работа ведётся через Issue, использовать тот же ID и зафиксировать ожидаемое поведение, границы и тесты.
4. Работать минимальным вертикальным срезом; не начинать широкую инфраструктурную переработку без ADR.

## При каждом изменении

- Провести unit, integration и, если требуется, isolated apt/dnf VM тест. Для сетевых/криптографических модулей — негативные тесты.
- Обновить документы, которые меняются вследствие реального поведения. Если реальность противоречит ADR, зафиксировать результат R и новое предложенное решение. Обсудить с владельцем.
- Выходить из задачи только с техническим доказательством выполненных условий. Ведите журнал `docs/process/decisions-and-evidence.md` после появления реальных артефактов.

## Рабочие статусы

Статусы хранятся только в `TASKS_RU.md`: `TODO -> READY (зависимости выполнены) -> IN_PROGRESS -> TESTING -> DONE`. Допускается `BLOCKED` с причиной и резервным сценарием. Нельзя завершать интеграционную работу из-за одного пройденного mock unit test вместо штатного E2E.

## Принцип исследования

R-исследования имеют явные условия PASS/FAIL/INCONCLUSIVE и fallback. Если выбранная гипотеза не подтвердилась, не «чинить» чужую систему ради теста, а предложить оговорённый безопасный ограниченный режим.

## Отчёт на завершение

Кратко: ID; что сделано; команды и выход; негативные тесты; файлы; новые риски; ADR; что остаётся; **подтверждено или только предположено**.
