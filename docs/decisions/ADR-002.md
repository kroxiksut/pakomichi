# ADR-002 — Семейства системных пакетов из одного Git-проекта

**Статус:** принято как проектное решение (концепция); эксплуатационные свойства проверяются исследованиями.
**Дата:** 2026-10-18.

## Контекст

Одно приложение может состоять из CLI/службы/общей части. Связь семейства подтверждается пользователем, не wildcard по префиксу.

## Решение

Один repo может содержать несколько разрешённых семейства/имён `.deb`/`.rpm`, из одного CI и одной кодовой базы. Новые версии разрешённого имени проверяются автоматически; новые имена требуют расширения allowlist.

## Альтернативы и причины отказа

Один repo = один пакет — отклонено; доверять любому новому `.deb` автора — отклонено.

## Последствия и ограничения

Решение обязательно для проектирования API, состояния и тестов. Если конкретная версия ОС не обеспечивает указанное поведение, нельзя объявлять поддержку этой комбинации без ограничения функциональности. Любое изменение решения требует новой superseding ADR и подтверждения владельца проекта.

## Подтверждение

Acceptance: R-001/e2e семейный upgrade; конфликт Provides/Obsoletes и новый пакет held.
