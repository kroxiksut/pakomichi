# ADR-009 — Разделение привилегий и ограниченный API

**Статус:** принято как проектное решение (концепция); эксплуатационные свойства проверяются исследованиями.
**Дата:** 2026-10-18.

## Контекст

Пакеты из интернета — недоверенные байты; доступ к ключу и системной конфигурации должен иметь минимум процессов.

## Решение

Fetch/inspect/verify — без root; привилегированный helper только применяет наши repo/keyring файлы; local signer защищён. HTTP read-only; статус API read-only, без установки ПО.

## Альтернативы и причины отказа

Выполнять maintainer scripts при inspection / запуск всего сервиса root / открытый network control API — отклонено.

## Последствия и ограничения

Решение обязательно для проектирования API, состояния и тестов. Если конкретная версия ОС не обеспечивает указанное поведение, нельзя объявлять поддержку этой комбинации без ограничения функциональности. Любое изменение решения требует новой superseding ADR и подтверждения владельца проекта.

## Подтверждение

Негативные тесты на недоверенные архивы, path traversal, SSRF, IPC permissions.
