# ADR-013 — SQLite + проверенный CAS и транзакционное применение ОС

**Статус:** принято как проектное решение (концепция); эксплуатационные свойства проверяются исследованиями.
**Дата:** 2026-10-18.

## Контекст

Объёмные пакеты не хранить в базе; после сбоя можно восстановить истинное состояние из проверенных файлов и журнала.

## Решение

SQLite хранит состояния и решения, файлы в CAS по SHA. Применение конфигурации ОС использует журнал намерений, staging, rename, проверку и reconcile; не считать SQLite+ФС одной транзакцией.

## Альтернативы и причины отказа

Хранить blobs в SQLite / произвольно восстанавливать trusted sources по текущему GitHub API — отклонено.

## Последствия и ограничения

Решение обязательно для проектирования API, состояния и тестов. Если конкретная версия ОС не обеспечивает указанное поведение, нельзя объявлять поддержку этой комбинации без ограничения функциональности. Любое изменение решения требует новой superseding ADR и подтверждения владельца проекта.

## Подтверждение

R-004 + E2E миграция схемы, powerloss, disk full и rollback.
