# ADR-005 — Два режима GitHub доверия Strict и Attested

**Статус:** принято как проектное решение (концепция); эксплуатационные свойства проверяются исследованиями.
**Дата:** 2026-10-18.

## Контекст

Значительная часть существующих Git Releases не immutable, но имеет attestations; исключать их без технической необходимости противоречит ценности проекта.

## Решение

Strict: immutable Release с проверенной release attestation. Attested: release может быть mutable, но проверены криптографическая artifact attestation, pinned repository ID и SHA конкретных байтов. Уже принятую запись никогда не перезаписывать на новый digest.

## Альтернативы и причины отказа

Только immutable, только GitHub SHA field, чистый TOFU без криптографического provenance — отклонены для автоматического режима 0.1.

## Последствия и ограничения

Решение обязательно для проектирования API, состояния и тестов. Если конкретная версия ОС не обеспечивает указанное поведение, нельзя объявлять поддержку этой комбинации без ограничения функциональности. Любое изменение решения требует новой superseding ADR и подтверждения владельца проекта.

## Подтверждение

R-003 проверяет реальные предикаты, embedded repo ID, rename/transfer, altered mutable assets.
