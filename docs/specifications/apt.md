# Контракт APT

## Выходы адаптера

- Для каждого активного логического источника — принадлежащий Pakomichi `.sources`/`.list` файл (по возможности современный deb822), уникальные поля `Origin`, `Label`, `Suite`, заданный `Signed-By` на *наш* keyring; не использовать глобальный `apt-key`/`trusted=yes`.
- Подписанный `InRelease` (при необходимости `Release.gpg`), `Packages`/`Packages.gz`, корректные поля checksums/architectures, `Acquire-By-Hash` и временная валидность `Valid-Until`.
- **Изначально низкий приоритет** Git-источника; для осознанно выбранного пакета — адресные правила, сверяемые `apt-cache policy`.

## Ограничения

- `apt_preferences` выбирает **версию**, а не экземпляр одинаковой версии из нескольких URL. При одинаковых NEVRA/версиях и разных байтах нельзя заявлять, что pin обеспечивает origin safety. `R-001`.
- Не переименовывать и не модифицировать чужие пакеты; не менять файлы чужих APT-репозиториев и глобальную политику.
- Двоичное совпадение SHA двух *доступных файлов* может свидетельствовать эквивалентности содержимого; требуется реально доказанный SHA, не только имя/версия.
- Активация — после чтения инвентаризации `dpkg`, репозиториев и проверенной симуляции транзакции `apt-get -s`, с пониманием ограничений этой симуляции.
- При неисполнимом режиме preferred оставить `observing`/`held`. Не изменять исходную версию пакета ради pin.

## Испытания

Debian 12/13, Ubuntu 24.04 (в матрице только при фактическом наличии изолированной среды). Два одинаковых `.deb` с одной версией, разными sha, перестановка order и Pin-Priority, выбранное семейство (main/service), обновление системной зависимости, пропажа local server, Valid-Until.
